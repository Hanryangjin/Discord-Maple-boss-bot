# 기획안 v2.2 구현 대조 및 검증

## 구현 범위

직업 목록·자동완성, 본인/관리자 대리 캐릭터 등록, 이름·헥환 검증, 소유자 정정, 상태 관리, 보스 관리·복구, 파티 생성·추가·제외·이동·병합·삭제, 개인 조회, 공개 파티 배분표, 관리 패널을 구현했다. DB 변경과 감사 로그·갱신 대기 기록은 같은 트랜잭션에 저장한다.

공개 게시 작업자는 운영·준비 세대, 단조 증가 렌더링 요청 버전, 스냅샷 완료 기록, 재시도, 중단·이전·메시지 정리를 사용한다. 일시 오류는 기존 운영을 유지하며 재시도하고, 준비 중 확정적인 채널·권한 실패는 새 준비 작업을 취소한다. 준비 작업과 미처리 정리는 DB에서 재시작 후 재개한다.

## 기획안과 다른 점·구현 결정

| 항목 | 현재 처리 | 영향 |
|---|---|---|
| 확인 버전 범위 | 개별 대상 버전에 더해 서버 전체 변경 revision을 보수적으로 검사 | 같은 서버의 무관한 변경에도 재확인이 필요할 수 있음. 안전성 유지, 사용성 차이 |
| 갱신 범위 | 도메인 변경 시 서버의 모든 보스를 dirty 처리 | 관련 보스만 갱신하는 최적화보다 API 요청 증가 가능. 연속 요청은 합쳐 처리 |
| 기본 직업 목록 | 패키지의 목록을 새 서버에 한 번 복사. 공식 안내 URL을 출처로 기록했으나 이 환경에서 대조 요청은 정책 403으로 차단 | 기획안의 ‘구현 시점 공식 목록 대조’는 미검증. 서버 관리자가 운영 전 목록을 확인해야 함 |
| 게시 생성의 불확정 결과 | 최근 100개 메시지에서 봇 작성자와 정확한 생성 마커를 대조해 재연결 | DB 기록 전 종료되고 메시지가 탐색 범위를 벗어나면 고아 메시지가 남을 수 있음. 완전한 외부 원자성은 보장하지 않음 |

전투력·보상 배분·주간 이력·자동 추천·웹 패널은 추가하지 않았다. 직업 비활성화는 기존 캐릭터와 배정을 유지한다. 보스 복구는 비활성 보스만 복구하고 이전 파티를 복원하지 않는다.

## 자동 검증

- 실제 SQLite에서 이름 중복, 서버 분리, 정원·동일 소유자 제한, 이동·병합 롤백, 정원 수동 축소, 대리 등록·권한, 소유자 정정, 직업 상태, 확인 중복·만료, 백업 복원 검증.
- 전송 모형으로 갱신 중 변경, 준비 중 비활성화, 게시 중단 도중 전송, 이전 권한 실패, 일시 오류·재시작, 오래된 정리 작업, 메시지 채택, 분할 수 감소 검증.
- discord.py를 사용해 실제 명령 payload 직렬화, 36개 명령, 서버 전용 설정, 문자열 헥환·직업 자동완성, UI 컴포넌트·persistent view 검증.

실행: `.venv/bin/python -m unittest discover -v`, `.venv/bin/python -m maplebot --check`.

검증 결과: 로컬 자동 테스트 **121개 통과**, `--check` 명령 구성 로드 성공, `pip check` 의존성 충돌 없음. CI 설정은 추가했으나 GitHub에서의 실행 결과는 아직 없다. Python 3.12에서 실행했으며 3.11은 CI 대상으로만 설정했다.

## 관리 UI 개선

두 가지 UI 수정 요구에 따라 단일 개인 메시지 전환과 Components V2 카드 표시를 추가했다. 기존 Embed 표시 방식을 대체하며 웹 패널은 추가하지 않는다. 메타데이터 복구·기존 게시물 변환을 포함한 내용은 [UI 개선 명세](ui-update.md)를 참고한다. 기존 도메인 테스트를 포함해 63개 로컬 테스트가 통과했다.

## 실제 Discord 검증 범위

사용자가 기존 버전의 실제 실행 성공을 확인했다. 이 환경에는 `DISCORD_TOKEN`과 테스트 서버가 제공되지 않아 이번 UI 변경의 실서버 검증은 별도로 실행하지 않았다. 로그인, 명령 동기화, 실제 채널 게시·이전, Discord 권한 오류, Gateway 멤버 이벤트, 선택 메뉴·모달의 실제 사용자 경험은 검증하지 않았다. Discord API/Gateway 네트워크 접근도 운영 환경에서 확인해야 한다. 저장된 토큰을 출력하거나 임의 자격 증명을 만들지 않았다.

실서버 검증 순서: 테스트 서버 설치·명령 동기화 → 서버 관리자/파티 관리자/일반 멤버 권한 → 관리자 대리 등록 → 0~정원 구성 → 이동·병합·조회 → 게시·변경 자동 갱신 → 메시지 수동 삭제·채널 권한 제거 → 중단·재개·채널 이전 → 프로세스 재시작·탈퇴/재가입 → 백업 복원.

## UTF-8 파일 읽기 호환성

사용자 커밋 `8ecebf47696a72e15ae6d845f41ea9d7efa78603`과 동일하게 `schema.sql`·`jobs.json` 읽기에 `encoding="utf-8"`을 명시했다. 기본 인코딩을 UTF-8이 아닌 ASCII로 강제한 별도 Python 프로세스에서도 DB·한글 직업 목록 초기화가 성공하는 회귀 테스트를 추가했다.

## 캐릭터 아이콘과 Discord 아바타 합성

사용자 요구에 따라 작은 캐릭터 아이콘과 큰 원형 Discord 아바타를 하나의 투명 PNG로 합성하고 공개 카드·개인 관리 화면에 실제 파일로 첨부한다. 이미지 처리는 Pillow 13.0.0으로 수행하며 웹 서버는 추가하지 않았다. 직업별 SD 전환에서 DB 스키마 버전 2를 추가했다. 설정과 파일 배치는 [아이콘 폴더 안내](../assets/jobs/README.md) 및 [UI 개선 명세](ui-update.md)를 따른다.

추가 테스트는 합성 픽셀 위치·비율·투명도, 파일 크기·화소·경로 제한, 누락·손상·다운로드 실패의 대체 표시, 아바타·아이콘 변경 시 캐시 무효화, 다운로드 중복 방지, 개인 화면 첨부 제거, 공개 전송·수정·종료 시 첨부 교체, 실제 discord.py multipart 직렬화를 검증한다. 기존 48개와 새 15개를 합쳐 63개 테스트가 통과했다. 의존성 검사·명령 구성 로드도 통과했다.

기본 47개 직업 SD 이미지를 패키지에 포함했다. 사용자 추가 직업·누락·손상된 자료는 공통 대체 이미지를 사용한다. 실서버 CDN 다운로드·PC/모바일 표시 확인은 별도 확인이 필요하다.

## 보스 순서 조정

`/보스 순서`, 기존 수정 명령의 위치 지정, 관리 패널의 순서 화면을 같은 도메인 로직에 연결했다. 순위·권한·서버 범위·확인 요청·작업 충돌을 검증한다. 같은 채널의 준비 세대로 공개 게시물을 실제 순서대로 다시 생성한 뒤 전환·정리한다. 메시지 삭제·페이지 증가로 순서가 깨졌을 때도 재게시로 복구한다. Discord 메시지의 물리 위치를 단순 편집으로 이동할 수 없다는 제약에 따른 구현이다. 메시지 링크 변경과 일시적인 중복 표시는 README에 안내했다.

보스 순서 추가 후 최종 검증은 전체 77개 테스트 통과, 명령 구성 로드 성공이다. 순서 이동·경계값·권한·확인·재시작 보존, 실제 메시지 ID 순서, 재게시 준비 실패와 복구, 페이지 증가·메시지 삭제·이전 중 페이지 증가, 개인 패널 위/아래/직접 입력을 검증했다. 실제 Discord 채널에서의 물리 순서 확인은 새 코드 적용 후 수행해야 한다.

## 공개 배분표 연속 표시 확대

관리 패널과 공개 게시물의 컴포넌트 예산을 분리하여 2인 파티 3개를 한 공개 메시지에 표시한다. 빈 파티의 실제 컴포넌트 수도 반영하고, 한도 초과 시에만 분할한다. 큰 보스 제목은 첫 메시지, 관리·내 보스 버튼은 마지막 메시지에 두며 페이지 번호 대신 작은 계속 안내를 사용한다. 새 경계값·긴 이름·복구 메타데이터 테스트를 포함한 전체 81개가 통과했다.

## 직업별 SD 기본 이미지와 공통 대체 이미지

47개 기본 직업에 안정적인 이미지 키를 부여한다. 직업명 변경·비활성화로 연결이 바뀌지 않으며, 직접 추가한 직업은 이름이 같아도 기존 이미지를 임의 연결하지 않는다. 서버별 직업 ID 파일로 덮어쓸 수 있다. 기본 이미지의 출처·권리 안내와 고정 커밋·SHA-256·얼굴 자르기 좌표를 함께 기록했다.

DB 버전 1의 기본 직업 최초 등록 순서로 기존 자료를 연결한다. 전환은 트랜잭션으로 처리하여 실패 시 컬럼 추가와 데이터 변경을 함께 되돌린다. 재시작 시 기존 연결을 덮어쓰지 않는다. 비표준 DB에서 기본 직업 수가 모자라면 추측해서 연결하지 않고 대체 이미지를 사용한다.

전체 87개 테스트가 통과했다. 기본 자료 47개 해시·크롭 검증, 사용자 추가·이름 변경·서버 분리·덮어쓰기·손상·경로 탈출 방지, 기존 DB 전환·실패 롤백·재시작 보존을 포함한다. 포럼 게시 방식 전환은 이 직업 아이콘 변경에 포함하지 않는다.

배포 wheel을 빌드하고 별도 경로에 설치하여 내장 이미지 47개 포함, DB 초기화, 47개 얼굴 렌더링을 확인했다. 명령 구성 로드·의존성 검사·`git diff --check`도 통과했다.

## 레테 기본 직업·SD 추가

기본 직업을 48개로 늘리고 레테의 넥슨 직업소개 SD 원본을 고정된 공개 아카이브에서 포함했다. 파일 해시와 개별 출처·얼굴 크롭을 manifest에 기록하고 PNG도 배포 패키지에 포함한다.

DB 버전 3에서 기존 서버에 레테를 한 번 추가한다. 이미 같은 이름의 직업이 있으면 ID·활성 상태를 유지하고 빈 아이콘 연결만 채운다. 연결을 명시적으로 지정한 자료는 유지한다. 이후 이름 변경·비활성화는 재시작으로 되돌리지 않는다. 버전 1의 기본 47개 매핑 순서는 변경하지 않는다.

레테 추가 후 전체 90개 테스트, 명령 구성 로드, 원본 기록 해시 일치, 배포 wheel의 PNG 포함 여부를 확인했다. 실제 Discord 표시 확인은 적용 후 필요하다.

## Windows 자격 증명과 로컬 설정

`--token-set`·`--token-delete`로 Windows 기본 암호화 자격 증명 저장소만 직접 사용한다. keyring의 자동 백엔드 선택이나 일반 텍스트 대체 저장은 하지 않는다. 토큰 입력은 숨김 입력만 허용하며 저장소 오류의 원문이나 토큰을 출력하지 않는다. 환경 변수가 저장된 토큰보다 우선하고, Windows 외 환경은 환경 변수를 유지한다.

`--test-guild-set`·`--test-guild-delete`는 Git에서 제외되는 UTF-8 `config.local.json`을 원자적으로 교체한다. 서버 ID는 환경 변수 → 로컬 설정 → 전역 동기화 순으로 결정한다. 잘못된 명시 값·손상 파일은 오류로 종료한다. 등록 명령은 DB·Discord 접속 없이 처리하며 실행 중 프로세스는 재시작으로 적용한다. 자세한 사용법은 [로컬 설정 안내](local-settings.md)에 기록했다.

전체 110개 테스트가 통과했다. 숨김 입력 취소·저장소 오류 비노출·Windows 기본 백엔드 지정·영속 저장/삭제·우선순위·파일 교체 실패 보존·실제 명령 동기화 범위를 모의 전송으로 검증했다. Windows Python 3.11·3.12의 keyring 의존성 버전 및 조건도 메타데이터로 확인했다. 현재 실행 환경은 Linux이므로 Windows Credential Manager 실물 저장·읽기와 Discord 로그인은 사용자 환경에서 확인해야 한다.

## 직업 아이콘 단독 정사각형 표시

가로로 긴 아이콘·아바타 합성으로 Discord에서 이미지가 잘리는 문제에 따라 합성 방식을 96×96 직업 아이콘 단독 표시로 교체했다. 소유자 멘션은 유지하며 아바타 다운로드·캐시 코드는 제거했다. 공통 대체 이미지, 크기·화소 제한, 첨부 교체와 이미지 내용 기반 캐시는 유지했다. 가로·세로 이미지의 비율·양 끝 보존, CDN 미호출, 아이콘 교체 반영을 포함하여 전체 110개 테스트가 통과했다.

포럼 채널 게시 방식은 미구현 상태이며 별도 활성화 명령도 없다. 일반 채널 카드 방식과 구분하여 안내했다. 실제 Discord 클라이언트의 표시 결과는 사용자 환경에서 확인해야 한다.

## 포럼 게시와 파티 전체 2열 이미지

후속 승인 사항에 따라 기존의 포럼 미구현 상태를 해소했다. 포럼은 보스별 스레드 한 개를 만들고 분할 메시지는 같은 스레드에 둔다. 일반 채널에서 이전 시 새 준비 세대 전체의 성공 후 운영 전환·이전 게시물을 정리한다. `forum_topics`·`forum_routes`·`board_forums` 테이블은 시작 시 자동 생성한다. 세대 fencing·영속 재시도·중단 충돌 처리는 기존 작업자를 재사용한다.

정원·동일 소유자·직업·캐릭터 규칙은 변경하지 않았다. 이미지 방식은 기존 컴포넌트 텍스트 카드를 교체하고, 클릭 가능한 멘션과 버튼은 이미지 밖에 둔다. 한글 글꼴을 수정·번들하여 운영 OS의 폰트에 의존하지 않는다. 관리 화면도 같은 파티 이미지를 사용하고 캐릭터 상세는 직업 아이콘을 유지한다.

기획 대비 Discord 제약: 포럼 목록의 정렬은 봇 보스 순서와 같다고 보장할 수 없다. 순서 변경 시 포럼 스레드를 재생성하지 않는다. 중단·이전의 이전 포럼 게시글 삭제는 댓글도 함께 삭제하며, 전용 포럼 운영을 안내했다. 자세한 적용 순서·권한·탐색 범위는 [포럼 안내](forum-board.md)에 기록했다.

전체 121개 테스트가 통과했다. 생성·동일 보스 추가 페이지·재시작·불확정 생성 채택·보관/잠금 해제·삭제 후 복구·소유자 검증·권한 실패·일반 채널 이전·변경 갱신·중단 정리·순서 변경 보존과 0/홀수/6인 이미지, 외부 멘션·버튼을 검증했다. 실제 Discord 테스트 서버는 제공되지 않아 실서버 게시·PC/모바일 표시는 미검증이다.

배포 wheel을 별도 경로에 설치하여 포럼 테이블 자동 생성·한글 글꼴 포함·이미지 렌더링을 확인했다. 명령 구성 로드와 `git diff --check`도 통과했다.

# 기획안 v2.2 구현 대조 및 검증

## 구현 범위

직업 목록·자동완성, 본인/관리자 대리 캐릭터 등록, 이름·헥환 검증, 소유자 정정, 상태 관리, 보스 관리·복구, 파티 생성·추가·제외·이동·병합·삭제, 개인 조회, 공개 파티 배분표, 관리 패널을 구현했다. DB 변경과 감사 로그·갱신 대기 기록은 같은 트랜잭션에 저장한다.

공개 게시 작업자는 운영·준비 세대, 단조 증가 렌더링 요청 버전, 스냅샷 완료 기록, 재시도, 중단·이전·메시지 정리를 사용한다. 일시 오류는 기존 운영을 유지하며 재시도하고, 준비 중 확정적인 채널·권한 실패는 새 준비 작업을 취소한다. 준비 작업과 미처리 정리는 DB에서 재시작 후 재개한다.

## 기획안과 다른 점·구현 결정

| 항목 | 현재 처리 | 영향 |
|---|---|---|
| 확인 버전 범위 | 개별 대상 버전에 더해 서버 전체 변경 revision을 보수적으로 검사 | 같은 서버의 무관한 변경에도 재확인이 필요할 수 있음. 안전성 유지, 사용성 차이 |
| 갱신 범위 | 도메인 변경 시 서버의 모든 보스를 dirty 처리 | 관련 보스만 갱신하는 최적화보다 API 요청 증가 가능. 연속 요청은 합쳐 처리 |
| 기본 직업 목록 | 패키지의 목록을 새 서버에 한 번 복사. 공식 안내 URL을 출처로 기록했으나 이 환경에서 대조 요청은 정책 403으로 차단 | 기획안의 ‘구현 시점 공식 목록 대조’는 미검증. 서버 관리자가 운영 전 목록을 확인해야 함 |
| 게시 생성의 불확정 결과 | 최근 100개 메시지에서 봇 작성자와 정확한 생성 마커를 대조해 재연결 | DB 기록 전 종료되고 메시지가 탐색 범위를 벗어나면 고아 메시지가 남을 수 있음. 완전한 외부 원자성은 보장하지 않음 |

전투력·보상 배분·주간 이력·자동 추천·웹 패널은 추가하지 않았다. 직업 비활성화는 기존 캐릭터와 배정을 유지한다. 보스 복구는 비활성 보스만 복구하고 이전 파티를 복원하지 않는다.

## 자동 검증

- 실제 SQLite에서 이름 중복, 서버 분리, 정원·동일 소유자 제한, 이동·병합 롤백, 정원 수동 축소, 대리 등록·권한, 소유자 정정, 직업 상태, 확인 중복·만료, 백업 복원 검증.
- 전송 모형으로 갱신 중 변경, 준비 중 비활성화, 게시 중단 도중 전송, 이전 권한 실패, 일시 오류·재시작, 오래된 정리 작업, 메시지 채택, 분할 수 감소 검증.
- discord.py를 사용해 실제 명령 payload 직렬화, 35개 명령, 서버 전용 설정, 문자열 헥환·직업 자동완성, UI 컴포넌트·persistent view 검증.

실행: `.venv/bin/python -m unittest discover -v`, `.venv/bin/python -m maplebot --check`.

검증 결과: 로컬 자동 테스트 **34개 통과**, `--check` 명령 구성 로드 성공, `pip check` 의존성 충돌 없음. CI 설정은 추가했으나 GitHub에서의 실행 결과는 아직 없다. Python 3.12에서 실행했으며 3.11은 CI 대상으로만 설정했다.

## 미실행: 실제 Discord 검증

이 환경에는 `DISCORD_TOKEN`과 테스트 서버가 제공되지 않았다. 로그인, 명령 동기화, 실제 채널 게시·이전, Discord 권한 오류, Gateway 멤버 이벤트, 선택 메뉴·모달의 실제 사용자 경험은 검증하지 않았다. Discord API/Gateway 네트워크 접근도 운영 환경에서 확인해야 한다. 저장된 토큰을 출력하거나 임의 자격 증명을 만들지 않았다.

실서버 검증 순서: 테스트 서버 설치·명령 동기화 → 서버 관리자/파티 관리자/일반 멤버 권한 → 관리자 대리 등록 → 0~정원 구성 → 이동·병합·조회 → 게시·변경 자동 갱신 → 메시지 수동 삭제·채널 권한 제거 → 중단·재개·채널 이전 → 프로세스 재시작·탈퇴/재가입 → 백업 복원.

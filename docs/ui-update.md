# 관리 UI 개선: 단일 메시지와 Components V2

사용자가 승인한 두 요구(관리 메시지 누적 해소, 큼직한 Discord 카드 UI)를 기존 기획안 v2.2의 화면 표시 방식보다 우선 적용한다. 별도 웹 서버·로그인은 추가하지 않는다. 데이터·권한·배정 정책은 유지한다.

## 관리 화면

- `/관리 패널` 또는 공개 카드의 관리·편집·삭제 버튼에서 사용자별 개인 관리 메시지 하나를 생성한다.
- 탭, 소유자·캐릭터·직업 선택, 검색, 모달 제출, 변경 확인, 완료·오류 안내는 같은 메시지를 수정한다. 패널 내부에서는 `followup.send`로 중간 결과를 쌓지 않는다.
- 뒤로·관리 홈·닫기를 제공한다. 닫기는 관리 메시지를 삭제한다. 같은 사용자가 다시 열면 이전 세션을 비활성화하고 가능한 경우 이전 메시지를 삭제한다.
- 화면은 5분 동안 조작이 없으면 만료 안내로 바뀐다. 새 화면을 열어 계속 사용한다. 재시작 전 개인 화면은 재사용하지 않는다.
- 오래된 화면·모달의 제출, 다른 사용자 조작, 권한 회수 후 조작은 거부한다. 변경 확인의 서버 측 일회성 요청과 권한 검사는 기존 서비스를 재사용한다.

## 카드 표시

제목·보스명·파티명을 구분하고 Container·Separator로 파티별 카드를 만든다. 구성원은 큰 캐릭터명, 직업·헥환·소유자, 직업 SD 아이콘 썸네일을 한 행에 표시한다. 소유자는 멘션으로 표시하며 아바타는 합성하지 않는다. 이미지와 텍스트가 좌우로 배치되며 구성원 자체는 세로 목록이다. 자유로운 두 열 구성원 격자는 제공하지 않는다.

카드마다 편집·삭제 버튼을 제공한다. 공개 카드의 버튼은 공개 메시지를 개인 선택 화면으로 바꾸지 않고 해당 관리자의 개인 패널을 연다. 삭제는 별도의 확인 단계 후 실행한다. 권한이 없는 사용자는 공개 버튼이 보여도 수정하지 못한다.

메시지는 전체 40개 컴포넌트·4000자 한도를 검사한다. 인원이 적은 파티는 한 페이지에 함께 표시하고 6인 파티 등 큰 카드는 페이지를 나눈다. 25개 초과 선택 항목에는 페이지 이동·이름 검색을 제공한다.

## 공개 게시물 호환성

기존 Embed 게시물은 기존 DB 메시지 ID를 유지한 채 다음 갱신에서 Components V2로 변환한다. `content=None`, `embeds=[]`를 명시하여 기존 Embed를 제거한다. 데이터베이스 스키마 변경이나 데이터 초기화는 필요하지 않다.

공개 게시물 제목은 `스우 (익스트림)`처럼 보스명·난이도만 표시하고 뒤에 `파티 배분표` 문구를 붙이지 않는다. 화면의 `maple:...` 식별 문자열은 없애고 복구용 식별자는 버튼 `custom_id`에 보관한다. 재시작 후 동적 버튼을 등록하고, 메시지 검색·고아 메시지 복구는 이전 Embed footer와 새로운 버튼 메타데이터를 모두 읽는다. 기존 v1 공개 버튼 처리도 유지한다. 단, 이미 Components V2로 바꾼 메시지를 이전 코드로 되돌리면 기존 Embed 편집 경로와 호환되지 않을 수 있으므로 코드 롤백 시 게시물 처리도 별도로 고려해야 한다.

## 적용·확인

1. 새 코드로 봇을 재시작한다. discord.py는 기존 2.6.4를 그대로 사용한다.
2. `/관리 패널`을 새로 열어 화면 이동·수정 중 개인 메시지가 추가되지 않는지 확인한다.
3. `/파티배분표 새로고침`을 실행하여 기존 공개 게시물을 카드로 갱신한다. 재연결 시 자동 갱신도 요청된다.
4. 파티 카드 편집·삭제, 직업 선택·등록·수정, 뒤로·닫기, PC·모바일의 제목·직업 아이콘 표시를 확인한다.
5. 6인 파티·여러 파티·다른 관리자 동시 조작·중단/이전/재시작을 확인한다.

## 자동 검증과 제한

단일 루트 메시지 편집, 모달 제출 후 화면 갱신, 등록·확인·삭제, 검색·페이지, 중복 제출·권한 회수·만료, 6개 직업 아이콘과 컴포넌트/문자 한도, V2 공개 카드 직렬화, 기존 Embed 변환과 메타데이터 복구를 테스트한다. 실제 Discord PC·모바일 렌더링과 HTTP 수신은 이 변경에서 실행하지 않았으므로 사용자 테스트 서버에서 확인이 필요하다. 컴포넌트의 버튼 크기·폰트·배경·여백은 Discord 클라이언트를 따른다.

## 직업 SD 얼굴 아이콘 단독 표시

기존 200×128 아바타 합성 이미지는 Discord 썸네일에서 잘릴 수 있어 폐기했다. 직업 SD 얼굴 아이콘만 96×96 정사각형 PNG로 첨부하고, 소유자는 기존 멘션을 유지한다. 가로·세로로 긴 직접 지정 파일은 비율을 유지하여 여백 안에 넣고 추가로 잘라내지 않는다. 내장 SD의 얼굴 영역 추출 정책은 유지한다.

기본 직업 48개 자료와 누락·손상 시 공통 `?` 대체 이미지를 사용한다. 직업 ID 기반 파일 지정·이름 변경 시 연결 유지·DB 자동 전환은 [직업 아이콘 안내](../assets/jobs/README.md)를 따른다.

공개 카드·개인 관리 패널·캐릭터 상세에서 같은 정사각형 파일을 사용한다. 실제 첨부와 `attachment://` 참조를 함께 보내며, 메시지 수정 시 첨부 목록을 교체하고 이미지 없는 화면·종료·만료 시 이전 파일을 제거한다. 아바타 CDN 다운로드·실패 캐시는 제거했다. 파일 내용이 바뀌면 이미지 해시와 첨부 이름이 바뀌며 `/파티배분표 새로고침`과 관리 화면 재진입으로 반영한다.

새 코드로 재시작하고 `/파티배분표 새로고침`을 실행한다. 실제 PC·모바일에서의 최종 표시 크기는 Discord가 결정하므로 적용 후 확인한다.

## 보스 표시 순서

추가 요구로 기존 기획안의 ‘별도 보스 순서 명령은 두지 않음’을 변경하여 `/보스 순서 보스 위치`를 제공한다. 기존 `/보스 수정 표시순서`는 같은 위치 지정 로직을 공유한다. 위치는 활성 보스의 1~N이며 이동 시 다른 보스를 밀어 순위를 고유하게 재정렬한다. 목록·검색·패널·공개 메시지 게시 순서에 동일하게 적용한다.

관리 패널의 보스 화면 하단 **보스 순서**에서 현재 목록을 보고 위로·아래로 또는 위치 입력을 사용할 수 있다. 변경 확인과 결과는 같은 개인 메시지에서 처리한다. 게시 준비 중에는 중첩 순서 변경을 거부하고 UI 버튼을 비활성화한다.

기존 메시지 ID는 위치를 옮길 수 없으므로 같은 채널에 새 준비 세대를 순서대로 게시하고 전체 준비가 성공한 뒤 운영 세대를 교체한다. 원본 데이터·파티 배정은 유지하며 기존 메시지와 링크는 정리된다. 재시작 시 영속 작업을 재개한다. 이미 게시된 메시지의 삭제·분할 페이지 증가로 순서가 뒤집힌 경우에도 동일한 복구 경로를 사용한다. 권한 오류 시 기존 게시물은 보존하고 재생성 실패의 무한 반복을 막기 위해 재시도 간격을 둔다.

DB 스키마 변경은 없으며 기존 `sort_order`를 사용한다. 활성 보스의 새 등록·재활성화는 마지막 순위로 배치한다. 기존 값이 같은 보스는 ID를 보조 기준으로 사용하고 순서를 변경할 때 1~N으로 정규화한다.

## 공개 배분표의 연속 표시

개인 관리 화면은 선택·이동 버튼 공간을 남기지만 공개 배분표는 더 큰 카드 예산을 사용한다. 공개 메시지당 카드에 최대 36개 컴포넌트, 보스 제목·관리 버튼 등에 4개를 배정하여 전체 40개 한도를 지킨다. 2인 파티 3개는 한 메시지에 이어서 표시할 수 있다. 파티별 고정 개수 제한이 아니라 실제 인원·컴포넌트 수·문자 수를 기준으로 채운다.

Discord의 메시지 한도를 넘으면 한 보스의 메시지들을 연속 게시한다. 큰 보스 제목과 전체 파티 수는 첫 메시지에만 표시하고, 후속 메시지는 작은 보스명·계속 안내만 표시한다. 공개 화면의 페이지 번호 표기는 제거하며 관리 패널·내 보스 버튼은 마지막 메시지에만 둔다. 각 파티의 편집·삭제 버튼은 유지한다. 후속 메시지도 버튼 메타데이터를 갖고 있어 재시작 복구가 가능하다.

한 메시지에 무제한 파티를 담을 수는 없다. 컴포넌트 40개·텍스트 4000자·파일 첨부 10개라는 Discord 제한은 유지하며, 이 구성을 넘는 경우에만 분할한다. 개인 관리 패널의 페이지 이동은 유지한다.

레테 추가 업데이트는 DB 버전 3에서 기존 서버에도 한 번 반영한다. 같은 이름이 있으면 기존 직업 ID·활성 상태를 보존하고 빈 아이콘 키만 연결한다. 출처는 이미지별 manifest와 NOTICE를 따른다.

## 포럼 게시 및 2열 파티 이미지로의 변경

앞의 구성원 세로 목록·직업 단독 썸네일 방식은 파티 이미지 방식으로 교체했다. 파티마다 구성원을 2열 이미지로 표시하며 실제 멘션과 편집·삭제 버튼을 아래에 유지한다. 포럼 채널의 보스별 게시글 생성·갱신·보관 해제·재시작 복구와 일반 채널에서의 이전을 구현했다. [적용 안내와 기존 기능과의 차이](forum-board.md)를 따른다. 개인 관리 메시지 단일 전환과 기존 데이터·권한 정책은 유지한다.

# 메이플스토리 보스 파티 배분 디스코드 봇 개발 기획안

> 버전: 2.2 · 작성일: 2026-11-02  
> 상태: 구현 전 통합 명세. 본 문서를 검토한 뒤 구현에 착수한다.  
> 목적: 어떤 사용자의 어떤 캐릭터가 어떤 보스를 누구와 공략하는지 관리한다.

## 1. 범위와 용어

- **보스:** 이름과 난이도로 구분하는 운영 대상.
- **공략 조합:** 특정 보스에 배정된 캐릭터 집합. 문서와 화면에서 줄여서 “파티”로 표시한다.
- **파티 배분:** 캐릭터를 보스별 공략 파티에 배정하는 작업. 보상 배분 기능은 제공하지 않는다.
- **파티 배분표:** 보스별 파티와 구성원을 표시하는 공개 현황.
- **소유자:** 캐릭터에 연결된 Discord 사용자. 실제 게임 소유권 인증을 의미하지 않는다.
- **헥사환산(헥환):** 캐릭터의 선택적 참고 지표. 전투력 대신 사용하며 MVP에서는 사용자가 직접 등록·수정한 값을 저장한다.
- **직업 목록:** 서버별 관리형 목록. 캐릭터는 직업 이름 문자열이 아닌 불변 직업 ID를 참조하고 화면에는 직업명을 표시한다.
- **등록자:** 캐릭터 등록 작업을 수행한 사용자. 소유자와 다를 수 있다.

MVP는 Discord 네이티브 UI, 수동 캐릭터 등록, 수동 파티 배분, 단일 프로세스·SQLite를 사용한다. 서버별 고정 활성 회차 하나에서 최신 파티 배분만 관리한다. 주간 전환·과거 회차 재현·게임 API·자동 추천·웹 패널·이미지형 현황판·변경 요청 승인·일반 삭제 복구 도구는 후속 범위다. 단, 보스 소프트 삭제 복구는 MVP에 포함한다.

## 2. 확정 정책

1. 파티는 0명부터 해당 보스 정원까지 허용한다. 보스 정원은 1~6명이며 기본값은 6명이다. 6인 초과 확장은 가능 여부만 확인했으며 채택하지 않았다.
2. 동일 캐릭터는 같은 서버·보스·회차에서 활성 배정을 하나만 가진다. 서로 다른 보스에는 배정할 수 있다.
3. 같은 소유자의 서로 다른 캐릭터를 같은 파티에 넣지 않는다. MVP에는 경고만 허용하는 예외 설정을 두지 않는다.
4. 파티 표시명·순서와 별개로 불변 ID를 사용한다. 보스·캐릭터도 이름 대신 ID로 참조한다.
5. 보스 등록 시 파티는 자동 생성하지 않는다. 빈 파티를 별도로 생성한다.
6. 서버 간 보스·캐릭터·파티·회차·게시 메시지를 섞지 않는다.
7. 캐릭터 이름은 유일하다는 운영 전제를 적용한다. 서버 내 이름 중복은 소유자·등록자와 무관하게 금지하고, 다른 서버에서는 독립 등록을 허용한다. 비활성 캐릭터도 이름을 점유한다. 이름은 영문·숫자·한글로 구성하며 영문 대소문자는 동일하게 취급한다. 표시용 이름과 중복 검사용 이름 키를 분리하고, 이름 키는 NFC 정규화 후 ASCII 영문을 소문자로 변환하여 생성한다. 등록·수정 입력은 앞뒤 공백을 제거하고 내부 공백·특수문자는 거부한다.
8. 관리자는 현재 서버 멤버를 소유자로 지정하여 캐릭터를 대신 등록할 수 있다. 일반 사용자는 본인만 지정할 수 있다. 서버 미가입자의 선등록은 MVP에서 지원하지 않는다.
9. 소유자는 대리 등록된 캐릭터도 본인 캐릭터로 조회·수정할 수 있다. 등록자와 소유자는 별도로 기록한다.
10. DB 커밋 성공 후 Discord 갱신을 시도한다. DB 실패 시 갱신하지 않는다. Discord 실패 시 이미 커밋된 데이터를 되돌리지 않고 갱신을 재시도한다.
11. 정원을 줄일 때 새 정원을 초과하는 활성 파티가 하나라도 있으면 변경을 거부하고 파티와 인원을 안내한다. 관리자가 먼저 구성원을 수동 이동·제외한 뒤 재시도한다. 자동 제외·자동 이동은 수행하지 않는다.
12. 보스·파티 삭제는 MVP에서 소프트 삭제한다. 배정은 해제하되 캐릭터 원본과 변경 이력은 보존한다. 영구 삭제·일반 복구 기능은 후속 범위다. 보스 복구만 MVP에 포함하며 서버 관리자 전용으로 제공한다.

## 3. 역할과 권한

| 역할 | 허용 작업 |
|---|---|
| 일반 멤버 | 본인 캐릭터 등록·수정·활성화·비활성화, 캐릭터 목록·단일 캐릭터 조회, 보스 목록·현황, 내보스 |
| 파티 배분 관리자 | 일반 멤버 기능, 타인 캐릭터 대리 등록·수정·소유자 정정, 보스 운영, 파티 운영, 지정된 채널의 파티 배분표 게시·갱신·중단 |
| 서버 관리자 | 모든 기능, 관리자 역할·기본 및 실제 게시 채널 설정·이전, 보스 소프트 삭제·복구, 직업 목록 관리 |

서버 관리자는 Discord의 Administrator 권한으로 판단한다. 파티 배분 관리자는 서버별 설정에 저장한 역할 ID로 판단한다. 슬래시 노출 제한에만 의존하지 않고 명령·버튼·모달 제출 시 실행 권한과 서버 범위를 재검증한다. DM에서는 운영 명령을 사용할 수 없다. 확인 화면 이후에도 실제 변경 시점에 권한과 데이터 상태를 다시 검증한다.

## 4. 명령어

아래 명칭은 실제 그룹형 슬래시 구조를 기준으로 한다. 표시에는 ‘파티 배분표’를 사용하고 명령어 그룹은 공백 없이 `/파티배분표`로 표기한다. 객체 인수는 이름으로 검색하되 내부적으로 ID를 전달한다.

### 4.1 서버 설정

| 명령어 | 인수 | 권한·동작 |
|---|---|---|
| `/설정 관리자역할` | 역할 | 서버 관리자. 파티 배분 관리자 역할 지정 |
| `/설정 파티배분표채널` | 채널 | 서버 관리자. 기본 게시 채널 설정. 기존 게시물 이전은 게시 명령에서 별도 확인 |
| `/설정 조회` | 없음 | 관리자. 현재 역할·채널 설정 표시 |
| `/관리 패널` | 보스(선택) | 관리자. 개인용 파티·캐릭터 관리 패널 열기 |

### 4.2 보스 운영

| 명령어 | 인수 | 권한·동작 |
|---|---|---|
| `/보스 추가` | 이름, 난이도, 최대인원(기본 6) | 관리자. 동일 서버 내 이름·난이도 중복 방지, 정원 1~6, 파티 0개로 시작 |
| `/보스 목록` | 상태(기본 활성) | 일반 조회. 비활성·삭제 항목의 관리 조회는 관리자 전용 |
| `/보스 수정` | 보스, 이름/난이도/표시이름/표시순서/최대인원 | 관리자. ID 유지, 중복 검사, 정원 축소 정책 적용 |
| `/보스 비활성화` | 보스 | 관리자. 신규 배정·이동·병합 등 운영 편집을 막되 기존 배정 제외는 허용하고 일반 현황에서 숨김. 기존 데이터 보존 |
| `/보스 활성화` | 보스 | 관리자. 운영 재개 |
| `/보스 삭제` | 보스 | 서버 관리자. 영향 미리보기·2차 확인 후 보스와 연결된 활성 파티를 함께 소프트 삭제하고 관련 현재 배정을 해제 |
| `/보스 복구` | 보스 | 서버 관리자. 삭제된 보스를 비활성 상태로 복구. 이전 파티·배정은 자동 복원하지 않음 |
| `/보스 현황` | 보스 | 일반 사용자는 활성 보스만 조회. 관리자는 비활성 보스의 파티·배정도 조회. 삭제 보스는 관리자에게 삭제 정보·복구 안내만 표시 |

표시 순서는 `/보스 수정`으로 통합하며 별도 `/보스 순서`는 두지 않는다. 상태 변경·복구와 기존 배정 제외를 제외한 운영 편집은 활성 보스에만 허용한다. 삭제된 보스도 이름·난이도를 점유하며 동일 항목 재등록은 거부하고 복구 경로를 안내한다.

### 4.3 파티 운영

모든 변경 명령은 파티 배분 관리자 이상에게 허용하며 고정 활성 회차에서 수행한다. 원칙적으로 활성 보스에서만 실행하되 멤버제외는 비활성 보스에서도 허용한다. 삭제된 보스·파티에 대한 일반 변경은 거부한다.

| 명령어 | 인수 | 동작 |
|---|---|---|
| `/파티 생성` | 보스, 이름(선택) | 빈 파티 생성 |
| `/파티 이름변경` | 파티, 이름 | 표시명 변경 |
| `/파티 삭제` | 파티 | 구성원과 영향 표시·2차 확인 후 소프트 삭제, 해당 배정만 해제 |
| `/파티 멤버추가` | 파티, 캐릭터 | 활성 캐릭터·소유자의 현재 서버 소속, 정원, 중복, 동일 소유자 검증 후 추가 |
| `/파티 멤버제외` | 파티, 캐릭터 | 해당 배정만 해제 |
| `/파티 이동` | 보스, 캐릭터, 대상파티 | 같은 보스 내 현재 파티에서 대상 파티로 원자적 이동 |
| `/파티 병합` | 원본파티, 대상파티 | 같은 서버·보스·회차, 서로 다른 활성 파티인지 확인. 대상 정원·중복·동일 소유자 검증 후 일괄 이동하고 원본 소프트 삭제. 실행 전 확인 |

이동은 기존 배정이 있어야 하며 미배정 캐릭터는 멤버추가를 사용한다. 같은 파티로 이동하면 변경 없이 안내한다. 병합 확인 후 대상 버전·인원·상태가 바뀌었다면 최신 영향도를 표시하고 재확인한다. 실행 검증 실패 시 전체 변경을 취소한다.

### 4.4 캐릭터 등록·관리·조회

| 명령어 | 인수 | 권한·동작 |
|---|---|---|
| `/캐릭터 등록` | 이름, 직업(자동완성 필수 선택), 헥환(선택), 소유자(기본 호출자) | 일반 사용자는 본인, 관리자는 현재 서버 멤버 지정 가능. 이름 중복 검사, 소유자·등록자·등록시각 기록 |
| `/캐릭터 수정` | 캐릭터, 이름/직업(자동완성)/헥환, 헥환초기화(선택) | 본인 또는 관리자. 이름 변경에도 서버 내 중복 제한 적용, ID·배정 유지 |
| `/캐릭터 소유자변경` | 캐릭터, 소유자 | 관리자. 정정 전후 표시·확인. 현재 서버 멤버인지, 기존 파티에 동일 소유자 충돌이 생기는지 검증. 충돌 시 거부 |
| `/캐릭터 목록` | 사용자(기본 본인), 상태(활성/비활성/전체, 기본 활성) | 사용자의 등록 캐릭터 표시 |
| `/캐릭터 조회` | 캐릭터 | 한 캐릭터의 보스별 파티·동료 표시 |
| `/내보스` | 없음 | 본인 전체 캐릭터의 배정 표시 |

등록 완료 전 캐릭터 이름·직업·소유자를 확인한다. 직업은 활성 직업 목록의 자동완성 후보에서 선택하며 서버는 전달된 직업 ID의 현재 서버 소속과 활성 상태를 실행 시 재검증한다. 임의 문자열이나 다른 서버 직업 ID는 거부한다. 직업 수정을 생략하면 기존 직업을 유지한다. 비활성 직업을 가진 캐릭터도 다른 항목 수정은 가능하지만 새 직업 지정은 활성 직업만 허용한다. 동시 등록은 DB 고유 제약으로 최종 차단한다. 중복 시 기존 등록 정보를 안내하며, 비활성 캐릭터는 재등록이 아닌 재활성화 경로를 안내해야 한다. 헥사환산은 선택 정보이며 자동 추천에는 사용하지 않는다.

캐릭터 상태 명령:

| 명령어 | 인수 | 권한·동작 |
|---|---|---|
| `/캐릭터 비활성화` | 캐릭터 | 소유자 또는 관리자. 비활성 보스를 포함해 현재 배정이 있으면 거부한다. 일반 소유자에게는 비활성 보스의 상세 대신 관리자 정리 필요 안내를 제공하고 관리자는 전체 배정 목록을 확인한다. 관리자가 수동 제외한 뒤 실행 |
| `/캐릭터 활성화` | 캐릭터 | 소유자 또는 관리자. 비활성 캐릭터가 자동완성에서 검색되도록 제공. 현재 소유자가 서버 멤버인지 확인 후 재활성화. 과거 배정은 복원하지 않음 |

비활성 캐릭터는 신규 배정용 선택 목록에서 제외한다. 수정·소유자 정정·상세 조회·상태 관리의 자동완성은 해당 작업 권한과 상태에 따라 비활성 캐릭터도 포함한다. 상태 필터로도 조회할 수 있으며 이름·소유자·이력은 보존한다. 소유자 서버 탈퇴 시 데이터·기존 배정은 보존하고 탈퇴 표시 및 멘션 생략을 적용한다. 탈퇴 소유자의 캐릭터는 신규 배정·파티 이동·병합 대상에서 제외하며 기존 배정 제외는 허용한다. 같은 사용자 ID로 재가입하면 연결을 유지하고 정상 배정이 가능하다. 탈퇴 자체가 캐릭터의 활성 상태를 변경하지는 않는다. 관리자 소유자 정정은 현재 서버 멤버를 대상으로 가능하며 기존 충돌 검증을 적용한다.

### 4.5 파티 배분표

| 명령어 | 인수 | 권한·동작 |
|---|---|---|
| `/파티배분표 게시` | 채널(생략 시 마지막 실제 게시 채널, 최초 게시 시 기본 설정 채널) | 파티 배분 관리자는 지정된 실제 게시 채널에서 게시·갱신 가능. 최초 실제 게시 채널은 서버 관리자가 지정한 기본 채널 사용. 임의 채널 지정과 실제 게시 채널 이전은 서버 관리자 전용이며 영향 표시·확인 필요 |
| `/파티배분표 중단` | 없음 | 관리자. 영향 표시·확인 후 자동 갱신 중단, 기존 게시물 정리. DB의 보스·캐릭터·파티 데이터 보존 |
| `/파티배분표 새로고침` | 보스(생략 시 전체) | 관리자. DB 최신 상태 기준으로 갱신 대기 등록·처리 |

봇은 다른 사용자가 작성한 메시지를 수정하지 않는다. 임의 메시지 ID 연결은 MVP에서 제공하지 않는다. 재게시 시 같은 대상 채널의 기존 연결을 재사용한다. 채널 이전은 새 채널에 최신 게시물을 모두 생성한 뒤 활성 대상을 전환한다. 이전 게시물은 삭제하고 실패 시 가능하면 이전 안내를 표시한 뒤 정리 재시도를 기록한다. 새 게시가 실패하면 기존 채널 운영을 유지하고 새 채널의 부분 게시물은 정리한다. 이전·중단 작업 중 새 변경은 버전으로 추적하여 누락하지 않는다. 중단 시에는 활성 게시 상태를 먼저 해제하고 기존 게시물을 삭제하며, 삭제 실패 시 가능하면 중단 안내를 표시하고 재시도한다. 중단 후 새로고침은 재게시하지 않고 게시 명령을 안내한다. 다시 게시하면 최신 상태로 재개한다. 자동 갱신이 기본이며 새로고침은 수동 복구 수단이다.

### 4.6 직업 목록 관리

직업 목록은 서버별로 관리한다. 일반 멤버와 파티 배분 관리자는 조회·선택만 가능하고 목록 변경은 서버 관리자 전용이다. 목록 변경은 Discord 역할 권한이나 캐릭터 소유 관계를 바꾸지 않는다.

| 명령어 | 인수 | 권한·동작 |
|---|---|---|
| `/직업 목록` | 상태(활성/비활성/전체, 기본 활성) | 일반 사용자는 활성 목록, 관리자는 비활성·전체도 조회 가능. 검색·페이지 처리 |
| `/직업 추가` | 이름 | 서버 관리자. 직업 추가, 서버 내 이름 키 중복 검사. 캐릭터 직업을 자동 변경하지 않음 |
| `/직업 이름변경` | 직업, 이름 | 서버 관리자. 변경 영향 캐릭터 수 표시·확인 후 이름 변경. 직업 ID와 연결 유지, 관련 파티 배분표 갱신 |
| `/직업 비활성화` | 직업 | 서버 관리자. 영향 표시·확인 후 신규 선택 차단. 기존 캐릭터 직업·파티 배정은 유지 |
| `/직업 활성화` | 직업 | 서버 관리자. 비활성 직업을 자동완성으로 선택하여 재활성화 |

직업 영구 삭제·다른 직업으로의 일괄 병합 명령은 MVP에서 제공하지 않는다. 잘못 추가된 항목은 비활성화하고 필요한 캐릭터만 기존 캐릭터 수정 명령으로 정정한다. 비활성 직업 이름도 중복 제한에 포함하고 재추가 대신 활성화를 안내한다. 비활성 직업의 기존 캐릭터는 직업명과 비활성 표시를 보여주며, 캐릭터 자체가 활성이고 소유자·정원 등 조건을 만족하면 파티 배정은 가능하다. 직업 비활성화는 캐릭터 비활성화와 다른 정책이다.

직업 이름은 앞뒤 공백 제거 후 1~50자로 하고 내부 공백은 허용한다. 비교용 키는 NFC 정규화와 영문 대소문자 무시 기준으로 만들며 서버 내 고유 제약을 적용한다. 동명 직업이 자기 자신의 표시 대소문자만 변경하는 것은 허용한다.

초기 설치 시 구현 시점의 공식 직업 목록을 확인하여 버전 관리되는 기본 목록으로 준비한다. 새 서버 초기화 트랜잭션에서 기본 목록을 한 번만 복사한다. 봇 재시작·업데이트로 서버 관리자가 변경·비활성화한 목록을 덮어쓰거나 항목을 자동 재추가하지 않는다. 이후 신규 직업은 서버 관리자가 추가한다. 기본 목록에 빠진 직업은 임의 입력을 허용하는 대신 관리자 추가를 안내한다.

자동완성은 현재 서버의 활성 목록을 검색하고 최대 25개 후보를 반환한다. 입력 문자열 필터링으로 전체 목록을 탐색할 수 있어야 한다. 수정 명령은 현재 직업도 안내한다. 비활성화·활성화·이름변경 등 관리 명령은 작업에 필요한 상태의 직업을 검색한다. 자동완성에서 선택했더라도 실행 전 비활성화되었다면 새 등록·직업 변경을 거부한다. 패널·모달 경로에도 같은 검증을 적용하며 캐릭터 등록 모달에 자유 입력 직업 필드를 두지 않는다.

## 5. 화면과 사용 흐름

권장 채널은 `#보스-파티-배분표`, `#보스-관리`, `#캐릭터-등록`이다. 변경 요청 채널은 후속 기능 도입 시 추가한다.

관리 패널은 ‘파티 관리 / 캐릭터 관리 / 조회’를 버튼·선택 메뉴로 제공한다. 보스 선택 후 파티별 이름·인원·캐릭터명·직업·소유자 멘션을 표시한다. 파티 생성·편집·삭제·멤버 추가·제외·이동·병합은 명령어와 같은 검증 로직을 공유한다. 캐릭터 관리에서는 사용자를 선택하고 캐릭터 목록 및 현재 배정을 확인할 수 있다. 이동할 보스를 선택한 뒤 해당 보스의 대상 파티를 지정하며, 서로 다른 보스 사이의 배정을 자동 전환하는 기능은 아니다.

예시:

```text
타입 K / 파티 1 (3/6)
- 달빛제로 · 제로 · 헥환 5.25만 · @달빛
- 별하늘숍 · 비숍 · 헥환 미등록 · @별하늘
- 바람윈브 · 윈드브레이커 · 헥환 4.00만 · @바람
```

일반 단일 캐릭터 조회와 내보스는 활성 보스의 배정만 표시한다. 비활성 보스의 배정은 관리자가 관리 패널에서 조회한다. 단일 캐릭터 조회는 보스별 파티와 함께 공략하는 다른 캐릭터를 반환한다. 배정 없는 활성 보스도 구분하여 표시한다. 개인 조회와 관리 응답은 기본 ephemeral이며 공개 현황은 파티 배분표로 제공한다. 공개 현황은 Embed 기반으로 구현하며 자유로운 2열 카드·멤버별 아바타 배치는 요구하지 않는다.

초기 운영 흐름:

1. 서버 초기화 시 기본 직업 목록을 한 번 준비하고 서버 관리자가 관리자 역할·게시 채널·직업 목록을 확인한다.
2. 관리자가 보스를 등록한다.
3. 사용자가 직접 또는 관리자가 소유자를 지정하여 캐릭터를 등록한다. 직업은 활성 목록의 자동완성에서 선택한다.
4. 관리자가 빈 파티를 생성하고 캐릭터를 배정한다.
5. 관리자가 파티 배분표를 게시한다. 이후 DB 변경 성공 시 기존 게시물을 자동 갱신한다.

## 6. 데이터 설계

| 테이블 | 핵심 데이터·제약 |
|---|---|
| `guild_settings` | 서버 ID, 관리자 역할 ID, 기본 게시 채널 ID, 활성 게시 채널 ID, 게시 상태(미게시·게시중·중단), 단조 증가 세대 발급 번호, 운영 세대, 이전 준비 세대·대상 채널, 이전·중단 작업 상태. 중단 시 마지막 실제 게시 채널 ID 유지 |
| `discord_users` | 서버 ID+사용자 ID, 표시명 캐시, 소속 상태(재적/탈퇴 확인/확인 불가), 관측 시각, 마지막 재적 확인 정보. 표시명 대신 사용자 ID로 소유 관계 유지 |
| `jobs` | 직업 ID, 서버 ID, 표시 이름, 비교용 이름 키, 활성 상태, 속성 버전, 연결 변경 버전, 생성·수정시각. `UNIQUE(guild_id, name_key)`; 비활성 항목 포함 |
| `characters` | 캐릭터 ID, 서버 ID, 소유자 ID, 등록자 ID, 이름, 직업 ID(`job_id`, 같은 서버 직업 외래 키), 헥사환산(`hexa_value`, 선택, 원수치 정수; 5.25만은 52500으로 저장), 활성 상태, 버전, 생성·수정시각. `UNIQUE(guild_id, name_key)`; 표시용 `name`과 정규화·영문 소문자화한 `name_key` 분리 |
| `bosses` | 보스 ID, 서버 ID, 이름, 난이도, 표시명, 정원, 순서, 상태, 속성 버전, 구성 변경 버전 |
| `cycles` | 회차 ID, 서버 ID. MVP는 서버별 고정 활성 회차 하나 |
| `boss_groups` | 파티 ID, 서버 ID, 보스 ID, 회차 ID, 표시명, 순서, 상태, 버전 |
| `group_members` | 서버 ID, 보스 ID, 회차 ID, 파티 ID, 캐릭터 ID, 등록시각. 현재 배정만 저장하며 서버+보스+회차+캐릭터 고유 제약 |
| `board_messages` | 서버 ID, 보스 ID, 채널 ID, 게시 세대, 분할 순서, 메시지 ID, 반영 버전. 서버·세대·보스·분할 순서 고유 제약. 보스당 여러 메시지 지원 |
| `board_sync_state` | 서버 ID+게시 세대+보스 ID, 요청 버전, 완료 버전, 재시도 상태·시각·오류 분류. 세대별 보스 렌더링 요청을 추적. 외부 작업·정리 대상은 별도 테이블로 관리 |
| `confirmation_requests` | 일회성 요청 ID, 서버·요청자, 작업·대상 버전, 만료 시각, 상태, 처리 결과 |
| `board_jobs` | 작업 ID, 서버, 게시 세대, 유형(게시/이전/중단/렌더링/정리), 대상 채널, 상태·재시도 정보 |
| `board_cleanup_messages` | 정리 작업 ID, 채널·메시지 ID, 원래 세대, 정리 상태. 채널·세대가 다른 잔여 메시지를 개별 추적 |
| `audit_logs` | 서버 ID, 행위자 ID, 작업, 대상 ID, 변경 전후 값, 생성시각 |

DB 외래 키를 활성화하고 복합 참조 등으로 서버·보스·회차가 서로 일치하도록 보장한다. 중복 필드의 일관성을 애플리케이션 관례에만 맡기지 않는다. 파티 인원, 소유자 충돌, 소유자 정정, 정원 변경 검사는 변경과 같은 쓰기 트랜잭션에서 수행한다. 캐릭터 등록·직업 변경 시 직업의 서버 범위·활성 상태도 같은 쓰기 트랜잭션에서 재검증한다. 삭제·제외로 현재 배정을 제거해도 감사 로그를 남긴다. 감사 로그는 완전한 과거 회차 재현이나 자동 복구 기능을 대신하지 않는다.

## 7. 트랜잭션과 Discord 동기화

1. 요청자의 실행 권한, 서버 범위, 대상 상태·버전을 검증한다.
2. 쓰기 트랜잭션에서 최신 상태로 정원·중복·소유자 정책을 검증한다.
3. 실제 데이터 변경, 감사 로그, 관련 보스의 갱신 요청 버전을 같은 트랜잭션에 저장한다. 배정 제거·이동·삭제 전후의 영향 보스 집합을 확보하여 제거된 연결의 게시물 갱신도 누락하지 않는다.
4. 커밋 실패 시 전체 DB 변경을 취소하고 Discord 갱신을 실행하지 않는다.
5. 커밋 성공 후 작업자는 짧은 읽기 트랜잭션에서 요청 버전과 해당 보스의 렌더링 데이터를 같은 스냅샷으로 읽고, 트랜잭션을 종료한 뒤 Discord를 갱신한다.
6. 해당 스냅샷의 모든 필요 메시지 갱신·정리가 성공한 버전만 완료 처리한다. 외부 호출 뒤 최신 요청 버전을 읽어 이를 완료 버전으로 대신 기록하지 않는다. 갱신 도중 새 변경이 발생하면 추가 갱신을 수행한다.
7. 일시 오류·요청 제한은 지연 후 재시도한다. 권한 부족은 관리자에게 상태로 안내하고 대기 데이터를 보존한다. 재시작 시 미처리 갱신을 재개한다.

보스별 갱신은 직렬화하고 연속 변경은 합쳐 처리한다. 게시되지 않은 보스는 데이터만 저장하며, 게시 시 최신 상태를 렌더링한다. 화면 갱신 지연을 데이터 저장 실패로 안내하지 않는다. 삭제·비활성화된 보스의 기존 게시물은 운영 제외 안내만 남기고 구성원·직업·헥환 등 상세를 제거한다. 추가 분할 메시지도 정리하며 일반 활성 목록에는 표시하지 않는다. 재활성화 시 운영 세대에 최신 현황을 다시 렌더링한다.

Discord 메시지 생성·삭제와 DB 기록 사이에는 실패 구간이 있으므로 중복 게시·고아 게시물까지 완전한 원자성을 보장하지 않는다. 메시지 소유권·연결 상태를 검증하는 재조정 절차와 운영 안내가 필요하다.

## 8. 기술 선택과 외부 제약

- Python 3.11 이상, `discord.py` 2.x의 `app_commands`, View, Select, Button, Modal을 사용한다. 구현 시 지원 버전을 구체적으로 고정한다.
- SQLite 단일 프로세스 MVP로 시작한다. 비동기 DB 접근 또는 별도 실행 경로로 이벤트 루프 차단을 방지한다. 여러 인스턴스로 확장할 때 PostgreSQL 등을 검토한다.
- 봇 설치 범위는 `bot`, `applications.commands`를 사용한다. 게시 채널에 조회·메시지 전송·Embed 표시 등 필요한 권한을 확인한다. `GUILD_MEMBERS` intent를 코드와 Developer Portal에서 활성화하여 멤버 닉네임·탈퇴·재가입 이벤트를 처리한다. 캐시 누락 시 API로 확인하며 실패를 탈퇴로 취급하지 않는다. 필요 시 Discord의 intent 승인 요건을 확인한다.
- 토큰은 환경 변수로 주입하며 저장소·로그에 기록하지 않는다.
- 일반 문자열 선택 메뉴와 자동완성 결과는 최대 25개 항목으로 제한하고 검색·페이지 이동을 제공한다.
- Embed 개별 필드·필드 수·전체 문자 한도에 맞춰 페이지 또는 여러 메시지로 분할한다.
- 오래 걸리는 상호작용은 초기 응답 기한인 3초 이내에 defer한다. 지속적인 복구 작업은 상호작용 응답 토큰에 의존하지 않는다.
- 고정 메시지 연결을 DB에 저장한다. 공개 persistent view는 안정적인 `custom_id`와 재등록을 구현하고, 버튼 실행 시 권한을 다시 확인한다. 오래된 개인 패널은 만료 후 다시 열도록 안내한다.
- 재렌더링은 `allowed_mentions`를 제한하여 반복 알림을 방지한다. 사용자 입력의 멘션·마크다운도 표시 시 안전하게 처리한다.
- SQLite의 일관된 백업 수단을 사용하여 정기·배포 전 백업을 수행한다. 실행 중 DB 파일을 단순 복사하는 방식에 의존하지 않는다.
- 봇이 관리하는 정원은 게임의 입장 제한을 변경하지 않는다. 실제 캐릭터 소유 인증은 제공하지 않는다.

## 10. 수용 테스트

### 권한·등록

- [ ] 서버 관리자만 관리자 역할·게시 채널을 설정한다.
- [ ] 일반 사용자의 타인 캐릭터 등록·수정·소유자 변경을 거부한다.
- [ ] 관리자가 현재 서버 멤버를 소유자로 대리 등록하고 등록자와 소유자를 구분하여 기록한다.
- [ ] 대리 등록된 캐릭터를 소유자가 즉시 조회·수정할 수 있다.
- [ ] 같은 서버의 동일 이름 등록·이름 수정은 소유자와 무관하게 거부하며 비활성 이름도 포함한다.
- [ ] 사용자와 관리자가 동시에 같은 이름을 등록해도 하나만 성공한다.
- [ ] `Maple01` 등록 후 같은 서버에서 `maple01`·`MAPLE01` 등록과 다른 캐릭터를 해당 이름으로 수정하는 작업은 중복으로 거부한다. 같은 캐릭터의 대소문자 표시 변경은 허용한다.
- [ ] 영문 대소문자를 달리 입력한 검색으로 같은 캐릭터를 찾고 화면에는 저장된 표시용 이름을 보여준다.

- [ ] 영문·숫자 12글자는 허용하고 13글자는 거부한다.
- [ ] 혼합 이름 `가나다abc123`은 가중치 12로 허용하고 `가나다abc1234`는 가중치 13으로 거부한다.
- [ ] 문자 종류와 무관하게 1자 이름은 거부하고 `a1`, `가a`, `가나` 등 2자 이름은 상한·허용 문자 조건 충족 시 허용한다.
- [ ] `ㄱㅏ`, `가ㄱ`, 조합용 자모 시퀀스, 비ASCII 영문·숫자는 거부하고 완성형 한글 음절만 허용한다.
- [ ] 다른 서버에서는 같은 이름을 독립 등록할 수 있다.
- [ ] 소유자 정정으로 동일 파티 내 소유자 중복이 생기면 변경 전체를 거부한다.
- [ ] 서버 미가입 소유자 지정과 다른 서버 객체 ID 접근을 거부한다.
- [ ] 오래된 확인 화면·관리 버튼에서도 실행 시 권한·상태를 재검증한다.

- [ ] 같은 보스·회차의 동일 캐릭터 중복 배정 및 같은 파티의 동일 소유자 중복을 거부한다.

- [ ] 병합 시 같은 서버·보스·회차, 대상 정원, 소유자 충돌을 검증한다.

## 11. 추가 확정 정책과 캐릭터 이름 검증

캐릭터 비활성화 전 수동 배정 정리, 비활성 보스의 배정 제외 허용, 탈퇴자 데이터 보존과 신규 배정·이동·병합 제한, 게시 채널 이전·중단·정리 재시도, 서버 관리자용 보스 복구는 모두 승인된 MVP 정책이다. 각 명령·데이터 처리·수용 테스트에 반영한다.

이름은 영문·숫자·한글로 구성하며 영문 대소문자는 같은 것으로 취급한다. 표시용 이름과 중복 검사용 이름 키를 분리한다. 사용자가 제공한 길이·문자 규칙은 다음과 같이 적용한다.

- 모든 이름은 문자 종류와 관계없이 최소 2자다. 한글만으로 된 이름은 2~6글자다.
- 최대 길이 검사는 한글 1글자에 가중치 2, ASCII 영문·숫자 1글자에 가중치 1을 부여하고 합계 12 이하로 한다. 실제 UTF-8 바이트 수를 사용하지 않는다. 이는 사용자가 제시한 환산 규칙을 구현 명세로 정리한 것이며 공식 규칙을 별도로 검증했다는 의미는 아니다.
- 영문·숫자만으로 된 이름은 2~12글자다. 혼합 이름도 동일한 가중치 상한을 적용한다.
- 공백·특수문자는 허용하지 않는다. 입력 앞뒤 공백은 기존 정책대로 제거한 뒤 저장·검증하고, 내부 공백은 거부한다.
- 영문 대소문자 동일 취급과 표시용 이름 보존 정책은 유지한다.

최소 길이는 가중치가 아닌 문자 수로 판단한다. 예를 들어 `a1`과 `가a`는 모두 최소 2자 조건을 충족한다. 한글은 완성형 음절 `가`~`힣`만 허용하며 영문은 ASCII `A-Z`, `a-z`, 숫자는 ASCII `0-9`만 허용한다. 단독 자음·모음 및 조합용 자모는 입력에서 거부한다. 따라서 입력 앞뒤 공백 제거 후 허용 문자 검사는 `[A-Za-z0-9가-힣]+`의 전체 문자열 일치(`fullmatch`)로 수행하고, 문자 수 2 이상 및 가중치 합계 12 이하를 모두 검증한다. 허용 문자 검사 전에 자모를 결합하여 허용 이름으로 바꾸지 않는다. 허용 문자 검사 후 NFC 정규화 및 ASCII 영문 소문자화로 이름 키를 생성한다. 길이·허용 문자 관련 미확정 사항은 없다.

## 12. 후속 확장 원칙

주간 이력 도입 전 파티의 회차 귀속 또는 스냅샷을 설계한다. 현재 파티 이름 변경·삭제가 과거 회차 표시를 바꾸지 않도록 한다. 게임 API는 제공 정보·접근 조건·소유 인증 가능 범위를 별도로 검증한다. 자동 추천은 헥사환산만이 아닌 역할·운영 조건을 정의한 뒤 설계한다. 웹·이미지 UI를 추가해도 권한과 배정 검증 로직을 재사용한다.

참고: Discord Application Commands 및 Interactions 공식 문서, discord.py Interaction API. 구현 시 해당 버전의 현재 제한과 동작을 재확인한다.


## 13. 갱신·외부 상태·확인 처리의 확정 보완

### 13.1 갱신 원인

파티·배정·보스 상태·정원·표시명·정렬 변경 외에도 캐릭터 이름·직업·헥사환산·소유자 변경은 해당 캐릭터가 배정된 모든 보스의 갱신을 요청한다. 직업 이름·활성 상태 변경도 해당 직업의 캐릭터가 배정된 모든 보스의 갱신을 요청한다. Discord 닉네임 변경·탈퇴·재가입은 영향받는 게시물의 갱신 원인이다. 외부 이벤트를 DB의 표시 캐시·소속 상태에 반영한 뒤 갱신 요청을 기록한다. 재시작 시 관련 멤버 상태를 재확인하여 누락된 이벤트를 보정한다. 헥사환산은 화면에서 표시하는 경우에 반영하며 파티 추천에는 사용하지 않는다.

### 13.2 게시 작업 조정

서버별 게시·이전·중단 상태 전환과 보스별 렌더링을 조정한다. 세대는 단조 증가 번호로 발급하고 **운영 세대와 이전 준비 세대**를 구분한다. 작업은 서버·세대·채널·유형을 보유한다. 운영 렌더링은 현재 운영 세대에서, 이전 준비 렌더링은 현재 승인된 준비 세대에서만 실행한다. 권한 있는 준비 작업을 운영 세대가 아니라는 이유로 폐기하지 않는다.

이전 중 기존 운영 세대는 유지하며 새 채널에는 준비 세대로 게시한다. 데이터 변경은 운영·준비 세대 양쪽의 관련 보스 요청 버전을 증가시킨다. 현재 활성 보스와 준비 세대에서 한 번이라도 렌더링·생성 요청된 보스의 합집합을 전환 검사 대상으로 삼는다. 각 대상의 DB 최신 요청 버전이 반영되고 비활성화·삭제된 대상의 상세 제거 및 불필요 메시지 정리까지 완료되었는지 짧은 DB 트랜잭션에서 확인한 뒤 운영 세대·채널을 전환한다. 보스 추가·활성화도 준비 세대에 렌더링 요청을 생성한다. 준비가 미완료이면 전환하지 않고 추가 렌더링한다. 전환 후 변경은 새 운영 세대에 기록한다. 실패 시 기존 운영을 유지하고 준비 세대를 취소·정리한다. 활성 보스가 0개이고 준비 세대의 잔여 상세 제거·정리가 모두 완료되었으면 새 현황 메시지 생성 없이도 지정 채널·세대 설정을 완료할 수 있다.

중단은 운영·준비 세대를 모두 무효화하고 각 세대 메시지를 정리 작업에 등록한다. 마지막 실제 게시 채널은 별도로 보존한다. 재게시에는 새 세대를 발급한다. 같은 채널에서 정상 게시 중인 재게시 요청은 기존 운영 세대를 사용해 갱신한다. 최초 게시·중단 후 재개는 메시지 준비를 완료한 뒤 운영 상태로 전환한다.

각 작업은 외부 요청 전과 응답을 DB에 반영하기 전에 자신의 세대·채널·작업 상태를 검사한다. 외부 요청 도중 무효화된 작업의 생성 메시지는 활성 연결에 등록하지 않고 정리 대상으로 남긴다. 정리는 기록된 세대·채널·메시지 ID만 대상으로 하며 현재 메시지를 채널·보스 단위로 일괄 삭제하지 않는다. 생성 성공 후 DB 기록 전 종료된 작업의 고아 메시지는 메시지 내 봇 생성 식별 정보와 제한된 이력 조회 등으로 재조정하고, 확실히 식별되지 않는 메시지는 임의 삭제하지 않고 관리 상태로 안내한다.

Discord와 DB의 완전한 원자성은 보장하지 않는다. 이전 준비 중 일시적인 중복 게시와 부분 갱신은 가능하나 완료·복구 후 현재 운영 세대의 최신 현황으로 수렴해야 한다. 영속 작업 상태와 기록된 메시지로 재시작 후 준비 재개·취소·정리를 수행한다.

### 13.3 서버 소속 판정

소유자 상태는 `재적 / 탈퇴 확인 / 확인 불가`로 구분하고 관측 시각을 기록한다. 캐시 누락·타임아웃·API 오류·권한 문제를 탈퇴로 간주하지 않는다. 확인 불가 시 캐릭터·배정과 마지막 확인 정보를 보존한다. 현재 소속 확인이 필요한 등록·신규 배정·이동·병합·소유자 정정·재활성화는 확인 불가 시 보류하고 재시도를 안내한다. 데이터 저장 실패나 탈퇴 확정으로 안내하지 않는다. 기존 배정 제외는 허용한다. 탈퇴가 확인된 경우에만 탈퇴 표시·멘션 생략·배정 제한 정책을 적용한다.

### 13.4 일회성 확인

등록·삭제·병합·소유자 정정·게시 이전·중단 등 확인이 필요한 작업에 일회성 요청 ID, 요청자, 서버, 작업 내용, 대상 버전, 만료 상태를 연결한다. 실제 변경과 요청 소비 기록을 같은 DB 트랜잭션에서 처리하며 중복 제출은 기존 처리 결과 또는 처리 중 상태를 안내한다. 버전이 변경되면 최신 영향도를 다시 확인받는다. 외부 게시 작업은 한 번만 작업 대기열에 등록하고 재시도는 같은 작업 ID로 진행한다. 권한은 실행 시 다시 검증한다.

멤버 추가·제외·이동·병합은 영향받는 파티 버전과 보스의 구성 변경 버전을 증가시킨다. 캐릭터 소유자 정정도 영향 파티·보스 버전에 반영한다. 보스 삭제 확인은 하위 파티·배정의 변경을 포함하는 구성 버전을 검사한다. 직업 이름변경·비활성화 확인은 직업 속성 버전과 연결 변경 버전을 함께 검사한다. 캐릭터 등록·직업 변경 시 해당 직업의 연결 변경 버전을 같은 트랜잭션에서 증가시켜 확인 이후 연결 변화가 있으면 최신 영향도로 재확인한다. 직업 변경 시 이전·새 직업 모두 갱신한다. 파티 생성·이름변경·삭제도 보스 구성 변경 버전에 반영하며, 삭제 확인에 표시하는 캐릭터 이름 등 영향 정보 변경도 확인 버전에 포함한다. 직업 영향 건수에는 활성·비활성 캐릭터를 모두 포함한다.

## 14. 헥사환산(헥환)과 입력 검증 확정 규칙

전투력 항목을 헥사환산(헥환)으로 대체한다. 전투력의 억 단위 축약·변환 규칙은 사용하지 않는다. MVP는 수동 등록·수정만 제공하며 자동 계산·외부 수집·전투력 환산·자동 추천은 제공하지 않는다.

### 14.1 입력·저장·표시

- 등록·수정 인수 `헥환`은 **만 단위 수치를 나타내는 문자열**로 받는다. 예: `5.25` 입력 → `헥환 5.25만` 표시 → 원수치 정수 `52500` 저장. 명령 설명에 입력 단위를 명시한다. 입력에는 `만` 문자를 붙이지 않는다. 문자열을 Decimal로 직접 해석하며 float를 거치지 않는다. 입력 앞뒤 공백 제거 후 ASCII 숫자와 선택적 소수점으로 된 일반 십진 표기만 허용하고 지수·구분 쉼표·부호·비유한 표기는 거부한다.
- 양수만 허용하고 최대 소수 둘째 자리까지 받는다. 셋째 자리 이상 정밀도를 요구하는 값은 오류로 안내하며 임의 반올림하지 않는다. 검증·변환은 이진 부동소수점 오차를 피하도록 Decimal 기반으로 처리한다. 입력의 끝자리 0은 값의 추가 정밀도로 간주하지 않는다.
- 화면에서는 소수 둘째 자리까지 고정 표시한다. 예: `5` → `5.00만`, `0.01` → `0.01만`. 원수치 저장은 만 단위 입력에 10000을 곱한 정수이며 이 입력 정밀도에서는 100의 배수다.
- 선택값이며 미입력은 NULL로 저장하고 `미등록`으로 표시한다. 0·음수·비유한 수치와 저장 정수 범위를 초과하는 값은 거부한다.
- `/캐릭터 수정`에 `헥환초기화` 옵션을 제공한다. 헥환 새 값과 초기화를 동시에 요청하면 거부한다. 초기화만 요청하면 NULL로 변경한다.
- 캐릭터 관리·상세 조회·공개 파티 배분표에서 헥환을 표시한다. 미등록도 표시하며 헥환 변경 시 배정된 모든 보스의 갱신을 요청한다.

### 14.2 일반 입력값

- 보스명: 앞뒤 공백 제거 후 1~50자.
- 난이도: 앞뒤 공백 제거 후 1~20자.
- 파티명: 앞뒤 공백 제거 후 1~50자. 생성 시 이름 생략은 기본 표시명 부여.
- 위 이름의 내부 공백은 허용하고 공백뿐인 입력은 거부한다. 캐릭터 이름에는 별도의 11절 규칙을 적용한다.
- 보스 중복 기준은 같은 서버의 보스명+난이도다. 비교용 키는 앞뒤 공백 제거·NFC 정규화·영문 대소문자 무시 기준으로 생성하고 DB 고유 제약으로 보장한다. 삭제된 보스도 포함한다. 내부 공백은 임의로 합치지 않는다.
- 수정 항목이 하나도 없으면 사용법을 안내하고 변경하지 않는다. 입력값은 있으나 현재 값과 같으면 변경 없음으로 안내한다.
- 같은 파티 표시명이 있어도 보스·파티 ID 등으로 구별한다.

## 15. 추가 수용 테스트

- [ ] 파티 배분 관리자는 지정 채널에서 게시·갱신·중단할 수 있으나 임의 채널 게시·이전은 거부한다. 서버 관리자는 채널을 이전할 수 있다.
- [ ] 보스 삭제 시 연결된 활성 파티도 소프트 삭제하며 복구 후 이전 파티가 활성 상태로 남지 않는다.
- [ ] 캐릭터 목록 상태 필터와 활성화 자동완성으로 비활성 캐릭터에 접근한다.
- [ ] 일반 사용자는 비활성·삭제 보스 현황에 접근하지 못하고 관리자는 정해진 관리 정보를 조회한다.
- [ ] 동일 캐릭터의 영문 대소문자 표시 수정은 성공하고 다른 캐릭터와 이름 키가 충돌하면 거부한다.
- [ ] 캐릭터 정보·Discord 닉네임·소속 상태 변경 및 재시작 후 상태 보정으로 영향받는 모든 게시물이 갱신된다.
- [ ] 중단·이전 중 실행되던 오래된 갱신 작업이 이전 게시 상태를 되살리지 않으며 생성 메시지는 정리된다.
- [ ] 멤버 캐시 누락·API 장애는 탈퇴로 처리하지 않으며 소속 확인이 필요한 변경만 보류한다.
- [ ] 확인 버튼 연속 제출·만료 요청·오래된 버전 제출로 중복 변경이나 중복 게시 작업이 발생하지 않는다.
- [ ] 등록·수정·상세 조회에서 전투력 대신 헥환을 사용하고 미입력은 미등록으로 표시한다.
- [ ] 헥환 변경 시 관련 게시물 갱신을 요청하며 전투력의 억 단위 변환이나 자동 환산을 수행하지 않는다.
- [ ] 헥환 `5.25` 입력 시 원수치 52500 저장 및 `5.25만` 표시가 일치한다.
- [ ] 헥환 0·음수·비유한 값·소수 둘째 자리 초과 정밀도·저장 범위 초과 입력은 거부한다.
- [ ] 헥환 초기화 시 미등록으로 바뀌며 새 값과 초기화 동시 요청은 거부한다.
- [ ] 공개 파티 배분표·관리·상세 조회의 헥환 형식이 일치한다.
- [ ] 보스명·난이도·파티명의 공백·길이와 보스 비교용 키에 대한 입력 검증 및 DB 중복 제약을 검증한다.
- [ ] 수정 항목 없는 요청은 안내 후 변경하지 않으며 동일 값 요청도 불필요한 갱신을 만들지 않는다.

## 16. 게시 렌더링의 추가 동작

렌더링 결과와 현재 세대의 메시지 목록을 비교하여 기존 메시지는 수정하고 부족한 메시지는 생성하며 남는 메시지는 삭제한다. 파티 수 감소로 3개 메시지가 2개가 된 경우 세 번째 메시지를 정리한다. 실패한 정리는 개별 메시지 단위로 영속 기록·재시도한다. 중단·이전 세대의 메시지는 재생성하지 않는다.

- [ ] 분할 메시지 수의 증가·감소 시 생성·수정·삭제 후 DB 최신 상태와 화면이 일치한다.
- [ ] 기본 설정 채널이 바뀌어도 생략한 게시 명령이 마지막 실제 게시 채널을 임의로 이전하지 않는다.
- [ ] 확인 후 대상 버전 변경은 최신 영향도 재확인을 요구하며 확인하지 않은 새 상태로 실행하지 않는다.

## 17. 직업 목록 수용 테스트

- [ ] 등록·직업 수정에서 활성 직업 자동완성을 제공하고 임의 문자열·다른 서버 직업 ID·비활성 직업의 신규 지정을 거부한다.
- [ ] 직업이 25개를 초과해도 검색 문자열을 좁혀 전체 활성 항목을 선택할 수 있다.
- [ ] 일반 멤버·파티 배분 관리자의 직업 목록 변경을 거부하고 서버 관리자만 추가·이름변경·비활성화·활성화할 수 있다.
- [ ] 직업 이름 변경 시 기존 캐릭터의 직업 ID·배정은 유지하고 표시명과 관련 게시물이 갱신된다.
- [ ] 직업 비활성화 후 기존 캐릭터·배정은 유지되며 새 선택은 차단한다. 기존 캐릭터의 다른 항목 수정과 조건을 충족한 파티 배정은 가능하다.
- [ ] 비활성 직업은 재추가할 수 없고 관리자 활성화 검색으로 재사용할 수 있다.
- [ ] 같은 서버 직업 이름 중복·동시 중복 추가를 거부하며 다른 서버 목록에는 영향이 없다.
- [ ] 자동완성 선택 후 직업이 비활성화되면 등록·직업 변경을 실행 시 거부한다.
- [ ] 새 서버 기본 목록 초기화는 한 번만 수행되고 재시작·업데이트가 관리자의 기존 목록 변경을 덮어쓰지 않는다.
- [ ] 캐릭터 관리 패널에서도 슬래시 명령과 같은 직업 검증을 적용한다.

## 18. 실행 경로와 추가 검증

- SQLite 쓰기 트랜잭션은 쓰기 경합을 고려하여 짧게 직렬화한다. 같은 연결을 여러 코루틴이 공유하며 서로의 트랜잭션에 끼어들지 않도록 작업 단위 잠금 또는 전용 쓰기 실행기를 사용한다. 잠금 대기·실패는 명시적으로 처리한다.
- Discord API 호출은 DB 쓰기 트랜잭션 밖에서 수행한다. 외부 소속 확인 후 트랜잭션에서 DB 버전·직업 상태·배정 조건을 재검증한다. 소속 확인과 실제 탈퇴의 완전한 원자성은 불가능하므로 직후 탈퇴 이벤트는 기존 데이터 보존·탈퇴 표시 정책으로 처리한다.
- 자동완성은 일반 명령의 defer를 사용하지 않는다. 제한 시간 내 로컬 DB 검색으로 최대 25개 후보를 응답한다. 자동완성 요청 중 멤버 API 호출·게시·장시간 작업을 수행하지 않는다. 캐릭터 수정 권한과 서버 범위는 후보 조회에도 적용한다.
- 직업 선택 UI는 검색·페이지 선택과 등록 모달을 단계적으로 연결한다. 선택 직업 ID는 요청자·서버·등록 세션에 결합하고 최종 제출 시 같은 검증을 수행한다.
- 보스·파티·직업 상태 변경은 허용된 전이만 수행한다. 삭제 보스는 복구로만 비활성 상태로 돌아오고 활성화 명령으로 직접 살아나지 않는다. 같은 상태로의 요청은 변경 없음으로 안내한다.

추가 수용 테스트:

- [ ] 이전 준비 세대는 게시 가능하고 모든 최신 준비 결과가 완료되기 전에는 운영 세대를 전환하지 않는다.
- [ ] 이전 실패·중단·재시작 시 운영·준비 세대가 혼동되지 않고 기록된 이전 메시지만 정리한다.
- [ ] 직업 비활성화와 캐릭터 등록·직업 변경의 동시 실행에도 비활성 직업의 신규 연결이 생기지 않는다. 먼저 등록이 커밋된 경우에는 기존 연결 보존 정책을 적용한다.
- [ ] 비활성 캐릭터의 이름·헥환·소유자 정정이 가능하고 배정 검색에는 노출되지 않는다.
- [ ] 멤버·직업 연결 변경 후 오래된 확인 요청은 최신 영향도 재확인을 요구한다.
- [ ] 비활성·삭제 보스의 기존 공개 게시물에서 구성원 상세가 제거되고 재활성화하면 최신 상태로 표시한다.
- [ ] 헥환 문자열 `5.25`가 float 변환 없이 원수치 52500으로 저장된다.
- [ ] 자동완성이 defer 없이 제한 시간 내 응답하고 후보 조회에서도 권한·서버 경계를 지킨다.
- [ ] 삭제 보스에 활성화 명령을 실행해도 복구 절차를 우회하지 못한다.
- [ ] 렌더링 도중 추가된 변경을 이전 스냅샷의 완료 버전으로 잘못 처리하지 않는다.
- [ ] 배정 제외·이동·삭제 이후에도 이전 보스 게시물이 갱신된다.

- [ ] 이전 준비 중 보스 추가·활성화·비활성화·삭제가 발생해도 전환 후 필요한 현황이 누락되거나 이전 상세가 남지 않는다.
